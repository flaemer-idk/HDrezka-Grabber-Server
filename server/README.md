# HDrezka Grabber — сервер загрузок

Локальный сервер, который скачивает видео и субтитры **на себя** (а не на ноутбук)
и отдаёт веб-морду с очередью, прогрессом и настройками.

- **Без зависимостей**: нужен только Node.js ≥ 22.5 (используется встроенный `node:sqlite`).
  `npm install` не требуется.
- Скачивание с докачкой (Range), пауза/возобновление, автоповторы,
  продолжение загрузок после перезапуска сервера.
- HLS (`.m3u8`) — через `ffmpeg` (если установлен).
- Данные — в SQLite (`server/data/grabber.db`), файлы — в папке загрузок.

## Запуск

```bash
cd server
node src/index.js
```

Из командной строки меняется только порт — всё остальное живёт в веб-морде
(папка загрузок и медиатеки, шаблоны имён, категории, лимиты, токен):

```bash
node src/index.js --port 8081     # или -p 8081 / --port=8081
node src/index.js --help          # краткая справка
node src/index.js --version
```

Переменные окружения (нужны для systemd/NixOS): `PORT`, `HOST`, `DB_FILE`,
`DOWNLOAD_DIR`, `LIBRARY_DIR` (начальное значение папки медиатеки),
`AUTH_TOKEN`, `FFMPEG_PATH`, `USER_AGENT`.

## Установка на NixOS

Есть два варианта: самодостаточный модуль без флейков (`nix/hdrezka-grabber.nix`)
и флейк (пакет + модуль, `nix/module.nix`).

### Без флейков

`nix/hdrezka-grabber.nix` сам скачивает исходники с GitHub (`fetchFromGitHub`,
тег `v0.1.0`) и сам собирает пакет — достаточно скопировать файл в свой конфиг:

```bash
cp nix/hdrezka-grabber.nix ~/nixos/Custom/HDrezka/module.nix
```

```nix
# в конфиге
{
  imports = [ ./Custom/HDrezka/module.nix ];

  services.hdrezka-grabber-server = {
    enable = true;
    port = 8080;
    openFirewall = true;                  # чтобы расширение с ноутбука видело сервер
    dataDir = "/idkselfhost/HDrezka";                # база: история и настройки
    downloadDir = "/idkselfhost/HDrezka/downloads";  # куда качать (если не медиатека)
    libraryDir = "/idkselfhost/Media";               # начальное значение (потом — веб-морда)
    group = "media";                      # если медиатека общая с Jellyfin
    extraPackages = [ pkgs.ffmpeg ];      # для .m3u8 (HLS)
  };
}
```

Обновление версии: поменять `rev` на новый тег, поставить `hash = lib.fakeHash`
и запустить `nixos-rebuild switch` — Nix напишет настоящий хеш в ошибке.

### Флейком

```nix
# flake.nix вашей конфигурации
{
  inputs.hdrezka-grabber.url = "github:flaemer-idk/HDrezka-Grabber-Server";

  outputs = { nixpkgs, hdrezka-grabber, ... }: {
    nixosConfigurations.myhost = nixpkgs.lib.nixosSystem {
      modules = [
        hdrezka-grabber.nixosModules.default
        {
          services.hdrezka-grabber-server = {
            enable = true;
            port = 8081;
            openFirewall = true;                  # чтобы расширение с ноутбука видело сервер
            downloadDir = "/mnt/media/downloads";
            libraryDir = "/mnt/media/Jellyfin";   # начальное значение (потом — веб-морда)
            group = "media";                      # если медиатека общая с Jellyfin
            extraPackages = [ pkgs.ffmpeg ];      # для .m3u8 (HLS)
            # environmentFile = "/run/secrets/hdrezka.env";  # AUTH_TOKEN и т.п.
          };
        }
      ];
    };
  };
}
```

Что делает модуль: создаёт системного пользователя и каталоги, запускает сервис
`hdrezka-grabber-server` с автоперезапуском, ждёт монтирования папок
(`RequiresMountsFor`), ограничивает доступ (`ProtectSystem = strict`, запись —
только в свои каталоги) и при `openFirewall = true` открывает порт.

Без NixOS: готовый юнит лежит в `server/deploy/hdrezka-grabber-server.service`
(поправьте пути и пользователя, затем `systemctl enable --now hdrezka-grabber-server`).

Пакет отдельно:

```bash
nix build .#hdrezka-grabber-server     # ./result/bin/hdrezka-grabber-server --help
nix run .#hdrezka-grabber-server       # запустить сразу (данные в ~/.local/state)
```

> Nix-флейки видят только файлы, отслеживаемые git, поэтому перед первой сборкой
> добавьте их: `git add flake.nix nix server` (в этом репозитории они уже
> закоммичены). Без флейка пакет тоже собирается:
> `nix-build -E 'with import <nixpkgs> {}; callPackage ./nix/package.nix {}'`

Что внутри пакета: только `node` и обёртка-лаунчер (зависимостей нет — используется
встроенный `node:sqlite`). Обёртка задаёт разумные пути по умолчанию
(`$XDG_STATE_HOME/hdrezka-grabber/grabber.db`, `~/Downloads/HDrezkaGrabber`),
чтобы `nix run` работал без настройки; в Store ничего не пишется.

Логи цветные (уровни INFO/ГОТОВО/ВНИМАНИЕ/ОШИБКА, идентификаторы задач подсвечены)
и автоматически становятся простым текстом при выводе в systemd/journald или при
`NO_COLOR=1`.

В консоли появятся адреса, например:

```
http://localhost:8080/
http://192.168.1.50:8080/     ← этот адрес укажите в расширении
```

Откройте веб-морду в браузере — там очередь, прогресс и настройки.

### Переменные окружения (все необязательные)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `8080` | Порт сервера |
| `HOST` | `0.0.0.0` | Интерфейс прослушивания |
| `DOWNLOAD_DIR` | `server/downloads` | Папка загрузок (потом меняется в веб-морде) |
| `DB_FILE` | `server/data/grabber.db` | Файл базы данных |
| `AUTH_TOKEN` | пусто | Если задан — API требует заголовок `X-Auth-Token` (или `?token=`) |
| `FFMPEG_PATH` | `ffmpeg` | Путь к ffmpeg для HLS |
| `USER_AGENT` | Chrome UA | User-Agent для загрузок |

Пример:

```bash
PORT=8080 DOWNLOAD_DIR=/mnt/media/hdrezka AUTH_TOKEN=мойсекрет node src/index.js
```

### Автозапуск (systemd)

```ini
# /etc/systemd/system/hdzg-server.service
[Unit]
Description=HDrezka Grabber Server
After=network.target

[Service]
Type=simple
User=media
WorkingDirectory=/opt/hdzg/server
Environment=PORT=8080
Environment=DOWNLOAD_DIR=/mnt/media/hdrezka
ExecStart=/usr/bin/node src/index.js
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now hdzg-server
```

## Как это работает

1. **Расширение** (`client-extension/`) — открываете страницу фильма на hdrezka,
   нажимаете иконку, выбираете озвучку/качество/субтитры/серии. Расширение само
   достаёт прямые ссылки (через сессию вашего браузера) и отправляет задачи на сервер.
2. Сервер ставит их в очередь и качает файлы в папку загрузок по шаблонам имён.
3. Прогресс виден в веб-морде и в попапе расширения; загрузки продолжаются,
   даже если браузер закрыт.

Сервер **не умеет сам открывать страницы hdrezka** — сайт отдаёт серверу страницу
входа/«проверяем, что вы не бот». Поэтому разбор страницы делает расширение
(в браузере это работает), а сервер принимает уже готовые ссылки.

Дополнительно можно добавить задачу по прямой ссылке (`.mp4`, `.m3u8`, `.vtt`) —
форма в веб-морде, если ссылка уже есть на руках.

### Имена файлов по умолчанию

| Тип | Шаблон | Пример |
|---|---|---|
| Фильм | `%orig_title%%year_part%/%orig_title%` | `Kazakhs vs Aliens (2022)/Kazakhs vs Aliens.mp4` |
| Сериал | `%orig_title%%year_part%/%season_folder%/%orig_title%%sxxexx%` | `Mob City (2013)/Season 1/Mob City S1E1.mp4` |
| Субтитры | `%orig_title%%year_part%/%season_folder%/%orig_title%%sxxexx%.%subtitle_lang%` | `Mob City (2013)/Season 1/Mob City S1E1.rus.vtt` |

- Год — только на папке (`.mp4` его не содержит), берётся со страницы
  («Дата выхода»/«Год»), у сериалов — первый год диапазона (1999–2007 → 1999).
- Номера сезона/серии — без ведущих нулей (`S1E2`, `S1E10`).
- Имя субтитра совпадает с именем видео + код языка — так его подхватывает Jellyfin.
- Название выбирается по приоритету: английский вариант из «Romaji / English»
  → оригинальное → локализованное (русское).
- Слеши и запрещённые символы в названии не создают подпапок и не ломают имя.
- Старые значения по умолчанию мигрируют автоматически; свои шаблоны не трогаются.

## Настройки (в веб-морде)

Задачи сгруппированы: фильм/сериал → серия → файлы (видео и субтитры в одной
карточке). Группы сворачиваются. В строке состояния — оценка размера очереди
(«Осталось: ≈ …»): она считается по уже известным размерам и средним значениям
скачанного, без единого дополнительного запроса к сайту.

В шапке очереди есть кнопки «Остановить все» (отменяет всё, что качается и ждёт),
«Возобновить все» (снимает с паузы), «Повторить сбойные» и «Очистить завершённые». Опасные действия подтверждаются
вторым кликом по кнопке — без браузерных окон.

| Настройка | Смысл |
|---|---|
| Папка загрузок | Куда складывать файлы (на сервере) |
| Папка медиатеки | Пусто — качать в папку загрузок. Иначе файлы качаются сразу сюда (папки создаются автоматически) |
| Категории → папки медиатеки | Построчно: `films = Банановые фильмы`. Названия папок любые, это не хардкод — ключ `default` задаёт папку для остальных разделов |
| Одновременных загрузок | Сколько файлов качать параллельно (1–16) |
| Попыток на задачу | Сколько раз повторять при сбое |
| Пауза между попытками | Задержка перед повтором, сек (растёт с номером попытки) |
| Шаблоны имени | Отдельно для фильмов, сериалов и субтитров |
| Перезаписывать готовые файлы | При повторной загрузке заменять файл, а не создавать «Имя (1).mp4» |

Повторная загрузка безопасна: новый файл пишется во временный `.part` и заменяет
готовый только после полной загрузки. Если загрузка оборвётся, старый файл
останется на месте. Промежуточные `.part` содержат id задачи, поэтому две
загрузки с одинаковым именем не мешают друг другу и корректно докачиваются
после перезапуска сервера (включая `.part` от прежних версий).

Плейсхолдеры шаблонов: `%title%` (локализованное), `%orig_title%` (лучшее
название), `%quality%`, `%voiceover%`, `%year%`, `%year_part%` (« (2022)» или
пусто), `%season%`, `%season_id%`, `%episode%`, `%episode_id%`, `%sxxexx%`
(« S1E2»), `%season_folder%` («Season 1» или пусто), `%movie_id%`,
`%subtitle_lang%` (код языка: `rus`, `en`), `%subtitle_lang_raw%` (название как
его отдал сайт: `Русский`). Символ `/` создаёт подпапку; пустые сегменты
отбрасываются.

### Языки субтитров

В имени файла язык субтитров — всегда код, а не название: `American Psycho.rus.vtt`.
Код берётся так:

1. `subtitle_lns` из ответа плеера — если сайт отдал код сам (`Русский` → `rus`),
   расширение присылает его в задаче (`subtitle_lang_code`);
2. иначе — встроенный словарь сервера: `Русский` → `rus`, `Английский` → `en`,
   `Украинский` → `ukr`, `Русский (rus)` и `русский дублированный` тоже
   распознаются (регистр, скобки и лишние слова не мешают);
3. незнакомый язык переводится латиницей (`Португальский (Бразилия)` →
   `portugalskij`), чтобы в имени файла не было кириллицы.

В самой задаче (`subtitle_lang`) название языка остаётся как есть — его видно
в веб-морде. Хотите вернуть квадратные скобки — поменяйте шаблон субтитров на
`…%sxxexx% [%subtitle_lang%]`; хотите русское название в имени — используйте
`%subtitle_lang_raw%`.

## Медиатека (для Jellyfin)

Если указать «Папку медиатеки», файлы качаются **сразу туда** — без промежуточной
папки загрузок. Категория берётся из адреса страницы (`/films/…`, `/series/…`,
`/animation/…`, `/cartoons/…`), а имя папки вы задаёте сами в настройке
«Категории → папки медиатеки»:

```
films = Банановые фильмы
series = Банановые сериалы
animation = Аниме
cartoons = Мультики
default = Разное
```

Раскладка получается такой (структура узнаётся Jellyfin):

```
/path/медиатеки/Банановые фильмы/Kazakhs vs Aliens (2022)/Kazakhs vs Aliens.mp4
/path/медиатеки/Аниме/Mob City (2013)/Season 1/Mob City S1E1.mp4
```

Папки создаются автоматически; имена шаблонов (год, сезон, субтитры) настраиваются
там же — см. «Шаблоны имени». Задачи, созданные до включения медиатеки, сохраняют
старые пути: чтобы файл ушёл в медиатеку, добавьте задачу заново (из расширения
ссылки придут свежие).

## API

Авторизация (если задан `AUTH_TOKEN`): заголовок `X-Auth-Token` или `?token=`.
CORS открыт (`*`), чтобы расширение могло обращаться к серверу.

| Метод и путь | Назначение |
|---|---|
| `GET /api/state?limit=300` | Задачи, статистика, настройки, состояние сервера |
| `POST /api/tasks` | Добавить задачу (объект или `{tasks: [...]}`) |
| `POST /api/tasks/:id/cancel` \| `/pause` \| `/resume` \| `/retry` | Управление задачей |
| `DELETE /api/tasks/:id?file=1` | Удалить запись (с `file=1` — и файл с диска) |
| `POST /api/tasks/cancel-all` | Отменить все активные/ожидающие задачи (кнопка «Остановить все») |
| `POST /api/tasks/resume-all` | Возобновить всё, что стоит на паузе (кнопка «Возобновить все») |
| `GET /api/movies/:movieId` | Сводка по фильму: сколько скачано/в очереди/на диске (для предупреждения о повторе) |
| `POST /api/tasks/clear-finished` | Убрать завершённые/сбойные из истории |
| `POST /api/tasks/retry-failed` | Повторить все сбойные |
| `GET /api/settings`, `PATCH /api/settings` | Настройки |

Пример:

```bash
curl -X POST http://192.168.1.50:8080/api/tasks \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://cdn.example/movie.mp4","title":"Фильм","quality":"1080p","referer":"https://hdrezka.ag/films/..."}'
```

## Диагностика

- **`node:sqlite` не найден** — старый Node. Нужен ≥ 22.5 (`node -v`), лучше 24.
- **Хочу скачать фильм, но не хочу открывать расширение** — сервер не может сам
  открыть страницу hdrezka (антибот отдаёт ему страницу входа/проверки),
  поэтому разбор страницы всегда через расширение. Зато после постановки задачи
  качает уже сервер — браузер можно закрывать.
- **Задача «error: HTTP 403»** — CDN требует заголовки. Убедитесь, что у задачи
  заполнен `referer` (при разборе страницы он подставляется сам).
- **`.m3u8` не качается** — установите `ffmpeg` (`sudo apt install ffmpeg`).
  Что такое m3u8 — см. ниже.
- **Расширение не видит сервер** — проверьте, что адрес в настройках расширения
  совпадает с адресом из консоли сервера, и что файрвол пропускает порт
  (`sudo ufw allow 8080/tcp`).
- **Хочу закрыть доступ токеном** — запустите с `AUTH_TOKEN=...` и впишите тот же
  токен в настройках расширения.

## Частые вопросы

**Что такое `.m3u8`?**
Это не файл фильма, а «плейлист» HLS: текстовый список мелких кусочков видео
(сегментов), которые плеер скачивает по очереди. Если ссылка ведёт на `.m3u8`,
обычный загрузчик сохранил бы только текстовый список. Поэтому сервер при виде
`.m3u8` вызывает `ffmpeg`, который скачивает все сегменты и склеивает их в
обычный `.mp4`. Чаще всего hdrezka отдаёт прямые `.mp4`, а `.m3u8` встречается
на отдельных качествах/зеркалах.

**Сервер «прикидывается обычным пользователем»? Не забанят?**
Полной маскировки нет и быть не может. Как есть на самом деле:

- Запросы к API сайта (`/ajax/get_cdn_series/`) идут **из вашего браузера**
  (расширение), с вашими куками и сессией — с точки зрения сайта это те же
  запросы, что делает плеер при переключении озвучки/серии. Между запросами по
  сериям расширение держит паузу 0.4 с.
- Файлы скачиваются с CDN обычными HTTP-запросами (с `Referer` и User-Agent
  браузера), одним потоком на файл, без параллельных сегментов — это не
  агрессивнее, чем обычная закачка браузером.
- Сервер к самому сайту не обращается вовсе: он получает готовые ссылки.

На практике такой профиль почти неотличим от обычного пользователя, но 100%
гарантии никто не даст. Разумные меры: не качать сотни серий подряд одной
пачкой, не выкручивать `max_concurrent` до предела.
